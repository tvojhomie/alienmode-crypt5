# AlienMode: генератор и API для провайдеров

Node.js 22+; сторонние зависимости и установка npm-пакетов не требуются.
Генерация полностью локальная: модуль не скачивает подписку и не отправляет её Happ или AlienMode.
Для расшифровки нужен AlienMode build 22 или новее. Формат не совместим с Happ.

## Скачать

```sh
git clone https://github.com/tvojhomie/alienmode-crypt5.git
cd alienmode-crypt5
```

## CLI

Создайте файл `request.json` с правами 0600 (реальные токены не добавляйте в Git):

```json
{"url":"https://vpn.example/sub/personal-token","title":"Alien VPN"}
```

```sh
node cli.mjs < request.json > link.json
```

Ответ: `{"link":"alienmode://crypt5/am-2026-01.…"}`. Не передавайте исходный URL аргументом командной строки.
Ссылку из ответа можно использовать в QR-коде или кнопке «Добавить в AlienMode».
При создании HTML используйте безопасное экранирование атрибутов. Приложение должно быть установлено.

## Библиотека

Можно скопировать файлы модуля вместе с `recipient.json` или установить Git-зависимость:

```sh
npm install github:tvojhomie/alienmode-crypt5
```

При установке зависимостью импортируйте из `@alienmode/crypt5` вместо `./index.mjs`.
Для production закрепите проверенный commit в lockfile. В npm registry пакет не опубликован.

```js
import { encryptLink } from './index.mjs';
const link = encryptLink({ url: subscription.httpsURL, title: 'Мой VPN' });
```

`url`: HTTPS без логина/пароля, не более 16384 UTF-8 байт.
`title`: необязательное название, до 200 Unicode code points, без управляющих символов.
Одинаковый ввод каждый раз даёт новую зашифрованную строку. Приложение устраняет дубликаты по расшифрованному URL.
Наличие URL в базе не создаёт вторую подписку, повторное открытие обновляет существующую. Ручное название сохраняется.

## API на сервере провайдера

Создайте отдельный случайный токен авторизации, храните его в файле вне веб-каталога:

```sh
umask 077
node --input-type=module -e "import {randomBytes} from 'node:crypto'; process.stdout.write(randomBytes(32).toString('base64url'))" > api-token
ALIENMODE_API_TOKEN_FILE="$PWD/api-token" PORT=8787 node server.mjs
```

Сервис слушает **только 127.0.0.1**. Для удалённого доступа поставьте HTTPS reverse proxy (например Caddy):

```caddyfile
links.your-provider.example {
    log {
        output discard
    }
    reverse_proxy 127.0.0.1:8787
}
```

Замените домен, настройте DNS и сертификат. Не публикуйте HTTP-порт наружу.
API ключ нужен только серверу провайдера: не помещайте его в браузерный JavaScript, QR или клиентское приложение.
Для нескольких провайдеров нужны отдельные экземпляры/токены либо собственный шлюз авторизации и квот.

```http
POST /v1/links
Authorization: Bearer <API token>
Content-Type: application/json

{"url":"https://vpn.example/sub/personal-token","title":"Alien VPN"}
```

Машиночитаемая схема: [openapi.json](openapi.json).

Успех — HTTP 200 с полем `link`. Ошибки: 400 неверный ввод, 401 авторизация, 404 маршрут/метод,
413 тело >24 KiB, 415 Content-Type, 429 лимит 120 авторизованных запросов/мин на процесс.
Тайм-аут 15 секунд, ответ `Cache-Control: no-store`; тело запроса, токен и ссылки не логируются.
Отключите логирование тел/Authorization также в reverse proxy, APM и панели провайдера.
Не используйте API как публичный неавторизованный сервис. Генератор не проверяет доступность/право владения URL.

## Тесты

```sh
node --test test/api.test.mjs
```

Совместимость Node → CryptoKit проверена отдельно тестами клиентского приложения AlienMode. Исходники клиента и его ключ расшифровки в этот репозиторий не входят.
Производственный API на внешнем сервере в рамках локальной сборки не развёрнут.

## Что защищает формат

В SDK лежит только публичный ключ. Ключ расшифровки встроен в клиент, поэтому формат скрывает адрес
от обычного просмотра, но не от анализа приложения владельцем устройства. Зашифрованная ссылка остаётся
переносимым секретом доступа: её нельзя публиковать в логах. Общий ключ не заменяет авторизацию провайдера,
HWID, сроки действия, отзыв подписки и серверные лимиты. Любой обладатель публичного ключа может создать
корректную ссылку; цифровая подпись доверенного провайдера в v1 не реализована.

Ротация: новый `kid` + новая пара ключей + обновление приложения с сохранением старых ключей.
Нельзя менять пару ключей под существующим `kid`. Обновлять SDK провайдеров следует после доставки
нового декодера пользователям. Спецификация: [PROTOCOL.md](PROTOCOL.md).
